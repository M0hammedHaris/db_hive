# Epic 7: Post-MVP Enhancements & Integrations — Stories and Acceptance Criteria

This epic collects features that are valuable but intentionally out-of-scope for the canary MVP. These items are prioritized for Post‑MVP work after we validate core value propositions with early users.

## Stories

### Story 7.1: Plugin SDK (Post‑MVP)

- Description: Expose a stable plugin SDK to allow third-party extensions to transform query results or add custom visualizations.
- Acceptance Criteria: SDK docs published, 2 example plugins, plugin installation flow verified in staging.
- Estimate: 5 days (Post‑MVP)

### Story 7.2: Real-time Collaboration (Presence) (Post‑MVP)

- Description: Provide real-time presence, cursor indicators, and basic conflict resolution for simultaneous editing of visual queries.
- Acceptance Criteria: Presence indicators shown, basic conflict merge strategy documented.
- Estimate: 8 days (Post‑MVP)

### Story 7.3: Enterprise Connector Expansion (Post‑MVP)

- Description: Add ODBC/JDBC and specialized connectors for enterprise DBs beyond the MVP’s core databases.
- Acceptance Criteria: Two additional connectors validated with enterprise test data.
- Estimate: 5 days (Post‑MVP)

## Post‑MVP Deferment Note

The following features are explicitly designated as Post‑MVP. They are intentionally deferred from the canary MVP to reduce scope, speed up time-to‑value, and allow the team to validate core hypotheses first. When moving items back into scope, require a short business case and success criteria.

- Plugin SDK & Marketplace (defer)
- Real-time Collaboration (presence, conflict resolution) (defer)
- Enterprise Connector Expansion (ODBC/JDBC proxies beyond MVP DBs) (defer)

Acceptance Criteria for Deferment

- Each deferred item is added to the Post‑MVP backlog with: rationale, estimated effort, and required success metrics.
- No deferred feature is implemented during the MVP canary without explicit PM approval and updated risk assessment.
